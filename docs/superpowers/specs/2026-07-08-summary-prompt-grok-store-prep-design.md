# SumVid 改修設計書: 要約プロンプト強化 + Grok対応 + ストア提出準備

日付: 2026-07-08
設計: Fable (Agent) / 検証・統合: Sonnet

## 1. 概要とスコープ

ユーザーフィードバック「Gemini に要約させているが、要約内容が薄い。発言を引用できていない。動画の本質を捉えられていない」への対応として、以下3点を1つの設計にまとめる。

- **A. プロンプトテンプレート改修**: 全6テンプレートを引用駆動型に再構成し、肥大化した「批判的レビュー」セクションを簡素化する
- **B. Grok対応追加**: 対応AIサービスに Grok (`https://grok.com/` のみ、x.com 埋め込み版は対象外) を追加する
- **C. Chromeウェブストア提出準備**: STORE_LISTING.md / PRIVACY_POLICY.md / _locales の実態乖離を解消し、Grok追加を反映する

実装は本設計書に基づき別セッション(Sonnet)が行う。レビューは Fable Agent が行う。

## 2. プロンプトテンプレート改修設計

### 2.1 現状の問題分析

- 「批判的レビュー + 統合結論」セクション(A根拠調査/B批判/C統合結論)が6テンプレート全てにほぼ同一文言で末尾コピペされ、summary では全文の約半分を占める。プロンプト末尾はLLMの注意が集まりやすく、要約本体より批判レビューにトークンと注意が配分されている疑いが強い
- 「重要ポイント TOP5」が「説明2文以内」と制約され、引用・深掘りを構造的に排除している。keypoints も「1-2文」で同様
- 引用に関する指示は「タイムスタンプを正確に引用」のみで、**発言テキストの直接引用**を要求する指示がどこにもない
- 「動画の本質(なぜこの動画が存在するか・何が新しいか)」を問う出力項目がない

### 2.2 新しい共通構造方針

JSON は既存のフラットな「1テンプレート = 1 prompt 文字列」構造を維持する。文言レベルで以下の5層スケルトンに全テンプレートを統一する。

```
1. ロール定義 + 共通ルール     ← 共通層 (引用必須・一般論禁止・タイムスタンプ規則)
2. (テンプレート固有の追加ルール) ← 固有層 (必要なテンプレートのみ)
3. 動画情報                    ← 共通層 (プレースホルダ5種)
4. 文字起こし + injectionガード ← 共通層 (現行文言を維持)
5. 出力フォーマット             ← 固有層
6. 検証と結論 (簡素化版)        ← 共通層 (旧「批判的レビュー」の置換)
```

### 2.3 共通ルール層の完成版文言 (全テンプレートの「## ルール」に挿入)

```
## ルール
- 文字起こしの各行は [M:SS] 形式のタイムスタンプで始まる。出力にタイムスタンプを含める際は、文字起こし内の実際の時刻を正確に引用すること（例: [3:42]）。推測・捏造のタイムスタンプは使用禁止
- **引用必須**: 重要な論点には、文字起こしからの直接引用を必ず1つ以上含めること。引用は発言をそのまま「」で括り、タイムスタンプを添える（例: 「ここが一番のボトルネックです」[3:42]）。要約や言い換えは引用として扱わない
- **一般論の禁止**: 文字起こし内の発言に根拠を持たない一般論・推測・どの動画にも当てはまる記述は書かないこと。全ての記述を動画内の具体的な発言・数値・事例に紐づけること
- 文字起こしが長い場合は、動画の核心となる主張・数値・具体例を優先すること
- Web検索が利用可能な場合は、疑わしい主張の検証にのみ使用する（要約本体は文字起こしのみを根拠とする）
```

### 2.4 「批判的レビュー」簡素化後の完成版文言 (全テンプレート共通・末尾に挿入)

現行の約20行(A/B/C 3段構成)を約8行に削減する。Aセクション(根拠調査)は独立セクションとして廃止し、共通ルール層の「Web検索は検証にのみ使用」1行に吸収。Bセクション(批判)は「疑いがあるものだけ」に限定して残置。Cセクション(統合結論)は2-4点に圧縮して残置。

```
## 検証と結論（必須）

### 検証メモ
- 動画内の主張のうち、事実誤認・誇張・古い情報の**疑いがあるものだけ**を指摘する。フォーマット:「動画では **X** と主張 [M:SS] → 実際は **Y**。根拠: [ソース / 日付]」
- Web検索が使える場合は照合して根拠を示し、使えない場合は「知識カットオフ時点の情報」と明示する
- 該当がなければ「特筆すべき誤りは検出されず」と1行で書き、形式的に埋めないこと

### 統合結論
- 動画の主張と上記の検証を統合した最終見解を箇条書き2-4点で述べる。各点に確信度（高/中/低）を付ける
```

削除する要素: 「見落としなく出力に含めること」等の網羅要求、「反対意見・代替案・リスクを最低1つ」の強制(形式的な水増し出力の原因)、「動画公開日以降の状況変化の明示」の独立指示(検証メモの「古い情報」に包含)。

### 2.6 他5テンプレートの変更方針 (差分のみ)

全テンプレート共通の機械的変更: (i) 「## ルール」を2.3の共通文言に差し替え(テンプレート固有ルールはその下に追記)、(ii) 末尾「## 批判的レビュー + 統合結論 (必須)」ブロック全体を2.4の簡素化版に差し替え。

| テンプレート | 固有の変更 |
|---|---|
| `deepresearch` | 例外扱い。既存の主張抽出表・ファクトチェック・深掘り分析が旧Aセクションの機能を既に持つため、末尾の旧レビューブロックは丸ごと削除し「### 統合結論」(2.4のC部分のみ)を残す。主張抽出表に「直接引用」列を追加し、主張を話者の発言原文で裏付ける。「注目ポイント TOP5」に summary と同じ3要素構成(説明/引用/意義)を適用 |

### 3.3 ai-paste.js 追加エントリ (セレクタは全て要検証)

grok.com の実DOMは未調査。以下は一般的なチャットUI実装(textarea + form submit)からの推測候補であり、断定しない。実装時に3.5の手順で実DOMを確認し、確定したセレクタを先頭に置いた上で汎用フォールバックを残す。

```js
// AI_INPUT_SELECTORS に追加 — 全候補「要検証」
'grok.com': [
  'textarea[aria-label]',                        // 要検証
  'form textarea',                                // 要検証(汎用)
  'div[contenteditable="true"][role="textbox"]',  // 要検証(contenteditable型の場合)
  'textarea[placeholder]',                        // 要検証(最終フォールバック)
],

// AI_SUBMIT_SELECTORS に追加 — 全候補「要検証」
'grok.com': [
  'button[type="submit"]',        // 要検証
  'button[aria-label="Submit"]',  // 要検証(英語UI)
  'button[aria-label="送信"]',     // 要検証(日本語UI)
  'form button:last-of-type',     // 要検証(最終フォールバック)
],
```

注意点:
- **`src/lib/selectors.js` は変更しない**。当初 Fable はここにも同一エントリを追加するよう提案していたが、grep で確認した結果このファイルはどこからも import/参照されていない未使用コードであり、実装対象の `ai-paste.js` / `youtube-panel.js` のインライン定義とは無関係。触ると無関係な変更がdiffに混入するため対象外とする
- ai-paste.js がホスト名をどう解決しているかを確認し、`www.grok.com` で開かれた場合にもマッチするようにする(キー追加 or `hostname.replace(/^www\./, '')` 正規化)
- contenteditable ではなく textarea だった場合、貼り付け方式(input イベント / execCommand / value直接代入+イベント発火)が既存サービスと異なる可能性がある。既存の貼り付けロジックが textarea に対応しているか確認する(`insertText()` は既にtextarea分岐を持つため対応済みの見込み)

## 6. リスクと未決事項

1. **Grok実DOMセレクタ未検証(最大リスク)**: 3.3の候補は全て推測。実装セッションがPlaywrightで実DOMを確認してから確定する。確認不能な場合(アンチbot・ログイン壁)、実ブラウザでの手動DevTools確認に切り替える。セレクタ不一致時は既存のフォールバックチェーン設計により「貼り付け失敗→クリップボード経由の手動貼り付け」に縮退するはずだが、その縮退パスがgrok.comでも機能するかを検証項目に含めた(3.5-7)
2. **既存ユーザーのカスタムテンプレートへの影響**: カスタムテンプレートはchrome.storage.sync保存でありビルトインJSONとは別系統のため、prompt-templates.jsonの変更では影響しない見込み。ただし実装前に background.js のテンプレート読み込み経路(`SUMVID_GET_TEMPLATE`ハンドラ)を確認し、(a)ビルトインは常にJSONから読む、(b)カスタムはリセット対象外、の2点を保証すること(background.jsのコードを読む限り、この2点は既に満たされている見込みだが実装時に再確認する)
3. **host_permissions追加による再承認**: grok.com追加で既存ユーザーに拡張の再有効化・権限承認が求められる場合がある。ストア更新の審査でも権限追加理由の説明を求められる可能性があるため、提出時の説明文に用途(プロンプト自動貼り付け)を明記する
4. **defaultAIの既存乖離**: 既にスコープ外と明記(5章)。ストア提出前の動作確認で顕在化しうるため記録のみ
5. **プロンプト長の増加**: 引用必須化により出力が長くなり、無料枠モデルで出力が途中で切れる可能性。TOP5の各要素に上限(説明3-5文)を設けて総量を制御しているが、検証時に確認する(7章)
6. **Grokの日本語出力品質**: suffixで日本語指定するが、Grokの日本語遵守率は未検証。検証項目に含める

## 7. 検証方法 (実装完了後の手動確認手順)

自動テストが薄い前提で、以下を手動確認する。判定材料として改修前後の出力を同一動画で比較すること。

### 7.1 プロンプト改善の検証 (本丸)

対象動画: (a)技術解説系(数値・固有名詞が多い)、(b)対談/インタビュー系(発言引用の価値が高い)、(c)60分超の長尺、の最低3本。各動画×Gemini(フィードバック元)+Claudeの2サービスで実行し、以下を確認:

1. **引用の存在**: 重要ポイントTOP5の全項目に「」+ [M:SS]形式の直接引用が1つ以上あるか
2. **引用の実在性**: 引用のうち2-3個を抜き取り、YouTubeの文字起こしパネルで該当時刻を開いて、発言が実際に(ほぼ)原文どおり存在するか確認(捏造引用の検出)
3. **本質の把握**: 「動画の本質」セクションが動画固有の内容か。メタ記述や、動画名を伏せたら他の動画にも通用する記述になっていないか
4. **注意配分の是正**: 出力全体に占める「検証と結論」の分量が体感2-3割以下に収まり、要約本体が過半を占めるか
5. **一般論の排除**: 「実用的な知見」が動画内発言に紐づいているか。改修前出力と並べ、プロダクトオーナー自身が判定する(最終判定者はユーザー)
6. **出力切り詰め**: 長尺動画で出力が途中で切れないか
7. **他テンプレート回帰**: keypoints / notes / mindmapを各1回実行し、引用が入ること・フォーマット崩れがないことを確認

**合格基準(定性)**: プロダクトオーナーが改修前後の出力を見比べ、「引用がある・本質を捉えている・薄くない」の3点で改修後を選好すること。

### 7.2 Grok対応の検証

1. YouTubeパネルにGrokボタンが表示され、クリックでgrok.comが開く
2. プロンプトが自動貼り付けされ、自動送信される(3.5チェックリスト全項目)
3. 応答が日本語で返るか(suffixの効果確認)
4. 既存3サービス(ChatGPT / Gemini / Claude)の貼り付け・送信が回帰していないこと

### 7.3 既存ユーザー相当のアップグレード検証

1. 旧バージョンをインストール→カスタムテンプレートを1つ作成→新バージョンで上書き更新→カスタムテンプレートが残存し、ビルトインテンプレートは新プロンプトになっていることを確認(リスク2の実地検証)
2. `chrome://extensions`でエラーなし、権限再承認フローの挙動を記録

### 7.4 ストア提出前の最終確認

1. STORE_LISTING.mdのテンプレート一覧・サービス一覧がprompt-templates.json / AI_SERVICESの実態と一致(Quizが消えDeep Researchがある、4サービス)
2. Short Descriptionが132字以内
3. PRIVACY_POLICY.mdの第三者サービス一覧がhost_permissionsと一致
4. manifest versionが2.1.0、_localesの説明文が更新済み
